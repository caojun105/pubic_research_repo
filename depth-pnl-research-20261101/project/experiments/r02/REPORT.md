# R02：Release新增13小时冻结参数验证

完成日期：2026-11-03。原始数据来自 [btc-ws-data-20261103-batch01](https://github.com/caojun105/pubic_research_repo/releases/tag/btc-ws-data-20261103-batch01)。本轮无重新训练、无阈值搜索，不根据新数据换方向或选择冠军。上一轮的训练冠军OBI仍为主要验证对象，其他算法作为固定对照。

## 数据与完整性

13个完成分段、46,800个秒级样本；计划覆盖北京时间11月2日19:36:30至11月3日08:37:04（最后样本08:37:03），段间计划空档合计34秒。原始深度更新总数467,561。发布附件SHA256和清单内130个文件均校验，原始数据未改动。此批未包含原先11月1日的一小时；该批此前没有用于我们的参数选择，但仍只是一个夜间市场区间。

**13小时不等于13小时都能形成完整策略盈亏。** 首段19:36:30起的原始深度于19:41:16.159562发生超过1000ms的接收停顿，原引擎保守地要求新快照才能恢复，此段没有后续快照。部分模型当时有未平仓仓位，因此不编造卖出价，也不把后续缺失收益视为零。全部算法统一排除该首段，只比较其余**12个完整小时**。不是按收益好坏删小时；首段的已完成交易和未平仓原因保留在hourly输出中，未纳入总利润。

其他12段重建没有序号缺口、超时、会话错配、交叉盘口或信号范围不足。秒级记录与接收时刻重建出现15个可解释的发布延迟差异，0个无法解释差异：原始消息记录接收时刻，秒级记录选择处理后已发布的盘口；在同一updateId下核对价格一致。这不是新调参，但说明可用时刻仍采用代理假设。

## 固定实验设计

- 参数逐项沿用R01的selection.json，包括OBI入场0.4、退出0，不重新选择。全部输入和源代码哈希在结果JSON。
- 每笔0.01 BTC、Binance BTCUSDT现货做多/空仓，30秒最长持仓、500ms入场确认、300ms转弱退出。
- 100ms/500ms执行延迟；每边0/0.1/0.2/1bps费用。费用是研究假设，不是任何账户费率。延迟到达后的下一有效盘口逐档吃单；点差和可见深度冲击已含成交价。
- 每小时按预先记录的schedule独立从空仓开始、预留2秒清仓，不跨分段空档持仓。不把小时拼接当作毫无中断的13小时实盘。
- 不交易为0；买入持有也按每小时独立买卖0.01 BTC。仓位规模相同，不代表持仓时间、累计周转或风险相同。

## 对主要候选OBI的解释

零费净盈亏 **170.5396 USDT**，2338笔完整往返，胜率49.44%，平均每笔0.072942 USDT；12/12小时盈利。最差小时6.5881，最好小时24.0075；共同有效时段拼接的市值最大回撤2.5591 USDT。

最赚钱3笔占净利润2.47%，删去它们仍剩166.3269。与上一轮79.5%的集中度相比，本批盈利更分散。但相关的连续12小时不能当作12个独立市场环境，不据此年化。

双边累计成交名义额3617709.10 USDT。每边1bps费用为361.7709 USDT，超过170.54的毛利润，净亏191.2314。每边0.1bps后利润134.3625；0.2bps后98.1854。盈亏平衡约每边0.4714bps（约0.004714%）。每边1bps时，OBI每个有效小时均亏损。

延迟从100ms增至500ms，零费利润由170.5396降为139.2709，下降18.34%；每边1bps后为-215.8371。说明执行速度和费用都影响可兑现收益。

**更新后的判断：零手续费条件下的盘口信号证据比原先一小时更强；尚未形成通常费用假设下的盈利结论。** QI本批毛利润最高，但周转更高、费用容忍度低于OBI；不以本批结果替换原先选定候选。价格动量对照也盈利，因此盘口相对价格信息的增量价值还应做更严格的相同风险/周转对照。

## 验证和执行局限

27项现有单元测试通过。9个版本（8个策略与买入持有）×8个费用/延迟组合×13小时=936次仿真；其中896次完整仓位核账通过，首段40次存在未解决持仓。统一有效比较使用12×72=864次仿真。独立验证1,210,980项检查通过，冻结参数未改变。

本模型仍用原始接收时刻近似策略可用时刻，缺逐消息解析完成时间和真实下单回执。500ms压力测试不是实际延迟测量。没有竞速、隐藏流动性或订单自身市场影响模型；原始约100ms的合并更新无法恢复每笔挂单/撤单。没有maker排队成交证明。0.01 BTC的结果不能线性放大成大仓位收益。无已定义本金，不给本金收益率、年化或实盘保证。

## 复现与文件

在project目录运行（Python支持tarfile安全解压filter，系统有curl；不需要交易账户）：

```bash
python3 scripts/download_release_data.py --dest /absolute/path/release-data
python3 -m unittest discover -s tests -v
python3 -m depth_research.release_test --release-dir /absolute/path/release-data
python3 scripts/verify_release_test.py
```

下载和解压数据约占1.8GiB以上磁盘。Release URL与附件哈希见[release_assets.json](release_assets.json)。[summary.json](results/summary.json)、[aggregate.csv](results/aggregate.csv)、[逐小时基准](results/hourly_baseline.csv)、[数据审计](results/audit.json)、[验证记录](results/validation.json)入库保存。逐场景全量交易明细all_trades.csv约76MiB，由复现命令生成，避免再次大附件上传阻塞概要更新。
