默认每笔 0.01 BTC，Binance BTCUSDT 现货做多。训练40分钟选参数，测试20分钟固定参数评估。此小时以前已被研究过，以下是探索性时序留出结果，不是全新未见样本。

- **测试基准：零手续费、100ms延迟，17笔，净盈亏 +0.576596 USDT**，每笔平均 +0.033917 USDT，胜率 52.94%，平均盈亏比 4.7833，市值计价最大回撤 0.100200 USDT，平均持仓23.964秒。

- 测试盈亏平衡手续费约 **每边0.218041 bps**。可见零费盈利很薄，不能据此认为实际交易有利可图。

## 复现

在项目目录运行：

```bash
cd /home/ubuntu/depth-pnl-research
python3 -m unittest discover -s tests -v
python3 -m depth_research --config config.json --output results
python3 scripts/verify_results.py --results results
```

重新运行会覆盖所指定输出目录中的同名结果。输入位置可通过 `--data` 更改；`--output` 禁止位于输入数据目录内。仅审计使用：

```bash
python3 -m depth_research --config config.json --output audit_only --audit-only
python3 -m depth_research --help
```

`config.json` 提供订单量、窗口起点偏移、持续时间、训练时长、最长持仓、信号持续时长、断档阈值、期末清仓预留、参数网格及费用/延迟矩阵。默认训练选择基准固定为0 bps / 100ms，改变敏感性矩阵不会改变选择目标。默认网格4×4×2=32组；净收益相同选择遍历中的第一组。**只在训练段选择一次，测试和所有敏感性场景不重选参数。** 修改配置后必须重新运行和检验；验证器针对本任务的一小时实验约束。

## 因果重建和成交模型

快照只有到达 `available.local_mono_ns` 才可用。快照前增量缓冲，不能提前使用快照。仅在 `U <= lastUpdateId+1 <= u` 时应用新增量，`u <= lastUpdateId`为过期；数量0删除价位。快照与增量都用八位定点整数解析，拒绝更高精度输入。

只使用初始快照边界之间已证明完整的价格区间，不能因远处增量出现就扩大完整性范围。缺序、会话不匹配、接收断档超过1000ms、空/交叉盘口、六美元信号区间无法被证明覆盖时，盘口立即失效，停止交易；只有新快照再与序列衔接才能恢复。未平仓时遇到这些故障，结果显式标记不完整，而非虚构退出或消除亏损。

原始深度记录没有逐消息解析完成时间，接收时间作为可用时间代理，未测得的处理延迟由执行延迟假设近似。0ms并非理想抢先成交：仍要等信号事件之后的首个更新。因此真实有效等待还受约100ms更新粒度影响，逐笔CSV记录配置延迟以外的实际等待。

买入逐档吃ask、卖出逐档吃bid，用真实可见量计算完整0.01 BTC的VWAP；保存足够完成该数量的全部已知档位，不限80档。深度不足整笔拒绝；卖出拒绝不抹掉持仓。没有maker虚构成交，没有部分成交模型。可见历史盘口与策略订单互不影响，缺乏订单回执/竞速/隐藏流动性和历史交易过滤器，成交只是小额taker研究假设，不是实盘保证。

spread和逐档impact已包含在成交价内，不再额外扣减；手续费按买入和卖出各自名义额计算。没有杠杆、借币、资金费或跨所资金转移。执行期间锁定待成交订单，实际卖出之前不能再开仓。

## 策略和边界

参考价P为最优买卖中间价，六个1美元档（实际上是1 USDT价差）为买侧`(P−j−1, P−j]`、卖侧`[P+j, P+j+1)`，j=0…5。边界用整数两倍价格计算，不截断半个tick。B/A为六档BTC数量比，`bid1`为最优买档数量。入场要求`bid1 >= bid1_min`且`B >= ratio_in*A`、A>0并持续500ms；转弱定义为bid1不足或B/A降至ratio_out以下，持续300ms退出；30秒最长持仓独立触发退出。达到30秒后才发卖单，因此实际持仓会多出采样间隔和成交等待。

每个训练/测试段在结束前2秒安排卖出，最后`30秒+配置延迟+2秒`不再开仓。该清仓时刻预先确定，不能事后选择最后一条数据卖出。不能在分界外执行订单；若无法清仓就保留未平仓标记并将盈利结果判为不完整。测试从空仓和空信号状态重新开始，不继承训练信号。没有构造未来方向标签，避免超窗标签和跨段标签泄漏。

买入持有在同一段首可用事件发买单，使用同样延迟与逐档成交，并在相同期末预定时刻发卖单；只有单次仓位规模相同，不要求累计周转相同。不交易盈亏/回撤为0，胜率/盈亏比不适用。

## 指标与产物

- `summary.json`：配置、窗口、选择参数、训练/测试/拼接结果、基准、20组敏感性、代码和配置SHA256、复现命令、Python版本。
- `audit.json`：输入及旧参考SHA256、时间/完整性/时钟审计、序列异常计数、独立秒级交叉核验。
- `training_grid.csv`：32个候选训练表现。选择出的bid1下限0.5 BTC，入场比例2.0，退出比例1.0。
- `train_trades.csv`、`test_trades.csv`、`stitched_hour_trades.csv`：方向、BTC量、信号与成交时刻、VWAP、成交档数、实际延迟、退出原因、持仓秒数、毛盈亏、入场费、出场费、净盈亏。
- `*_equity.csv`：每个有效更新时点的累计净市值盈亏、已实现盈亏、持仓和回撤。持仓用mid标记，扣已发生的入场费；退出后扣实际出场费，不事先计提未来费用。回撤以0初始净值为起点，报告金额而不是本金百分比。
- `lat{毫秒}_fee{每边bps}_*`：每组测试逐笔/市值曲线、训练逐笔、买入持有逐笔与汇总。`sensitivity.csv`包含测试以及固定参数的训练、全小时分段拼接结果；全小时数据含选择样本。
- `book_features.csv`：每状态六个买/卖分档BTC数量、B/A组成、最佳报价、bid1及更新序号，便于外部复核信号定义。
- `run.log`、`tests.log`、`validation.log`与`results/validation.json`：实际运行、合成测试、输出独立复核记录。

净盈亏总额逐笔求和并核对`毛盈亏−双边费用`；平仓完整时必须等于末期净市值。胜率按净盈利笔数/总笔数，平局不算胜。平均盈亏比为平均正净盈亏/平均负净盈亏绝对值，profit factor为总盈利/总亏损绝对值；不存在分母时JSON为null。盈亏平衡每边bps为`毛盈亏 / 双边成交名义额 × 10000`；负值代表即使零费也亏损。

## 测试和局限

`tests/test_research.py`覆盖快照可用性、缓冲、序号衔接、缺序停机及重同步、过期消息、超时、会话切换、交叉盘口、快照范围、1美元档精确边界、逐档VWAP、深度不足、延迟执行、独立最长持仓、不能静默丢失期末持仓、未来数据不能改变训练、市值回撤、信号跨断档重置、训练/测试隔离和手续费核账。

`scripts/verify_results.py`独立读取输出，不调用回测逻辑：核对所有原始文件及旧参考哈希未变化、逐笔现金流、费用、持仓持续时间、信号/执行顺序、窗口边界、仓位无重叠、逐点回撤、末期平仓、全部20个场景汇总。

旧算法最大持仓只在弱信号分支生效、延迟卖出被提前记账、期末未平仓可能遗漏、回撤仅看平仓收益、超窗方向标签被末价替代；这些逻辑不能作为正确性标准。新旧结果不是单一错误的可比归因实验。数据只有一小时且已被旧研究看过，参数与策略范围也延续旧探索，因此仍可能过拟合；需要未来独立多日行情、真实费用与执行验证。报告不能证明长期有效，不提供年化或虚构本金收益率。
